## REFLECTION — CCM101 Cloud Computing: Enterprise Cloud Architect Project
As part of our final requirements for CCM101 – Cloud Computing, we worked on an Enterprise Cloud Architect project where we created a secure multi-tier web application using WordPress and MySQL. We followed a structured operational manual to set up our environment using VirtualBox, Ubuntu Server 24.04 LTS, Docker, and Docker Compose. This hands-on project gave us valuable end-to-end experience in deploying, managing, and maintaining a production-style web application infrastructure. A core task was deploying WordPress and MySQL as separate Docker containers, connected through an isolated private backend network. We used Docker volumes to store WordPress files and MySQL database data independently from the running containers. This configuration was critical: it taught us the importance of persistent storage design, ensuring that all our content and data remained intact and accessible even after restarting containers or rebooting the virtual machine. Security was another major focus. We hardened our server using UFW (Uncomplicated Firewall), blocking all incoming connections by default and selectively allowing only necessary traffic—port 22 for SSH management and port 80 for HTTP access. We deliberately kept port 3306 closed to the public, since MySQL only needed to communicate with WordPress over the private Docker network. This reinforced how network segmentation and least-privilege access rules are foundational to securing cloud-hosted applications. We also built reliability through automated backups. We wrote a Bash script that exports the WordPress database, removes backup files older than seven days to save space, and logs every action taken. Scheduled via cron, this runs automatically every day at 11 PM. We also documented and practiced a full restore workflow using saved SQL backup files. This module made clear that a robust backup and recovery plan is not just a best practice, but an essential safeguard against data loss. Finally, we performed thorough validation: after restarting containers and the entire virtual machine, we tested application availability, data persistence, and backup integrity. Our operational manual also included essential maintenance commands—for checking container status, reviewing logs, updating images, and monitoring disk and resource usage. Overall, this project bridged theoretical cloud concepts with real-world implementation. We gained practical skills in containerization, networking, security hardening, automation, and disaster recovery—core competencies for designing and managing secure, resilient enterprise cloud architectures.
