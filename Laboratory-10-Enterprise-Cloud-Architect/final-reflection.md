## REFLECTION
``` text
As part of our final requirements for CCM101 – Cloud Computing, we worked on an Enterprise Cloud Architect project where we created a secure multi-tier web application using WordPress and MySQL. To get started, we set everything up according to our operational manual, which guided us in using tools like VirtualBox, Ubuntu Server 24.04 LTS, Docker, and Docker Compose. This project was a great way to learn about all the steps involved in both launching and managing a web application.
One of the key tasks was to deploy WordPress and MySQL through Docker containers. Our manual provided detailed instructions on configuring these two services separately and linking them via a private backend network. We utilized Docker volumes to keep the WordPress files and database data intact. This was an essential part of the project because it taught us how crucial it is to set things up correctly and ensure persistent storage. This means that even when we had to restart the containers or the virtual machine, the data would still be accessible without any issues.
Another critical aspect we tackled was securing the server with UFW, or Uncomplicated Firewall. According to our instructions, we set it up so that all incoming connections were blocked by default, while allowing access on ports 22 for SSH and 80 for HTTP. We didn’t open the MySQL port (3306) because that database only needed to communicate with WordPress via the private Docker network. This experience helped us grasp how setting firewall rules and splitting networks can significantly enhance a web application's security.
We also implemented backup automation using a Bash script and cron jobs. The script was crafted to back up the WordPress database, clear out backup files older than seven days, and log its activities. We set up cron to automate the backup process every day at 11 PM. Additionally, we created a procedure to restore data using a previously saved SQL backup file. This taught us the importance of having reliable backup strategies and recovery methods for the database.
Our manual also emphasized testing the application post-restart of the containers and the virtual machine. These tests were essential to confirm that the application remained operational along with its stored data and backup disk. Moreover, the manual included maintenance commands and methods for troubleshooting issues like Docker permission errors or connection problems. This really rounded off our project as it addressed not just deployment but also ongoing maintenance.
In summary, our Enterprise Cloud Architect project deepened our understanding of various components involved in deploying and managing a web application. The procedures outlined in our manual taught us about virtualization, Docker, network setup, security measures, and the importance of backup and recovery. Overall, this project gave us a practical way to apply our knowledge of cloud computing while highlighting the responsibilities that come with managing a web application.
```
